# 固件协议与实现限制

本文件记录当前代码的字节布局。ESP32 节点交换基因组数据，由已经烧录的固件执行推理和进化。
UDP 端口为 `9999`，所有多字节整数均为小端。

## UDP 帧

`WormNet::sendTo()` 当前写出的字段如下：

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 `WR` |
| 2 | 1 | 消息类型 |
| 3 | 4 | `src_sig` |
| 7 | 2 | `plen` |
| 9 | `plen` | 有效载荷 |
| `9 + plen` | 2 | CRC16 |

发送端帧头字段共 **9 字节**。CRC 使用 CCITT-FALSE（初值 `0xFFFF`，多项式 `0x1021`），覆盖帧头和有效载荷。

| 消息 | 值 | 当前用途 |
| --- | --- | --- |
| `HELLO` | `0x01` | 广播节点存在，空载荷 |
| `HANDSHAKE` | `0x02` | 广播会话请求，空载荷 |
| `OFFER` | `0x03` | 向目标发送基因组 |
| `ACK` | `0x04` | 回复握手，空载荷 |
| `NOTE` | `0x05` | 向目标发送含经验的基因组 |
| `BYE` | `0x06` | 向目标发送会话结束通知，空载荷 |

`OFFER` / `NOTE` 载荷为 `[solved:1][fitness:2][genome:64]`，共 67 字节。
当前没有分片；`NOTE` 复用完整基因组布局。

## 基因组（64 字节）

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 1 | `version`，当前为 1 |
| 1 | 2 | `generation` |
| 3 | 2 | `fitness`，约定范围 0～10000 |
| 5 | 1 | `solved`，8 位位图 |
| 6 | 4 | `parent_sig` |
| 10 | 4 | `self_sig` |
| 14 | 40 | `int8` 权重，网络维度 8→4→2 |
| 54 | 8 | `int8` 笔记 |
| 62 | 2 | CRC16，覆盖前 62 字节 |

`self_sig` 使用 FNV-1a 计算：先把该字段清零，再对前 62 字节取指纹。
它用于节点识别与自接收过滤。CRC 和指纹均不提供身份认证。

## 已知实现限制

以下问题来自现有代码，仓库整理保留了当前通信行为与字节布局：

- **UDP 接收布局未对齐。** `HDR_SIZE` 为 10，而发送字段总长为 9；接收端从偏移 6 读取 `plen`，与发送端的偏移 7 不一致，载荷和 CRC 偏移也需统一。
- **接收缓冲生命周期及报文读取待修。** `Frame::payload` 指向 `receive()` 的栈缓冲，函数返回后失效；当前读取流程没有调用 `WiFiUDP::parsePacket()`。
- **发送返回值不代表接收成功。** 握手超时后仍会发送 `OFFER` / `NOTE`；返回值仅检查写入 socket 的字节数，没有基因组接收确认。
- **步骤位图宽度不足。** `N_STEPS` 为 10，但 `solved` 只有 8 位，第 8、9 步的学习状态无法保留。修改位宽需要同步调整序列化布局与协议版本。
- **内存自检不等于收到的数据校验。** `Genome::check()` 重新序列化并计算 CRC；接收字节的 CRC 校验在 `deserialize()` 中完成。

这些限制需要单独修复并进行多板通信验证。Python 模拟器独立于 UDP 实现，使用四阶段概率模型。
