# 固件协议与实现限制

本文件记录当前代码的字节布局。ESP32 节点交换基因组数据，由已经烧录的固件执行推理和进化。
UDP 端口为 `9999`，所有多字节整数均为小端。当前协议版本为 **基因组 v2**。

## UDP 帧

`WormNet::sendTo()` 当前写出的字段如下：

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 2 | 魔数 `WR` |
| 2 | 1 | 消息类型 |
| 3 | 4 | `src_sig` |
| 7 | 2 | `plen` |
| 9 | `plen` | 有效载荷 |
| `9 + plen` | 2 | CRC16 |

发送端与接收端帧头字段共 **9 字节**（`HDR_SIZE = 9`），`plen` 与 CRC 偏移已对齐。
CRC 使用 CCITT-FALSE（初值 `0xFFFF`，多项式 `0x1021`），覆盖帧头和有效载荷。
接收端对短帧、魔数不符、未知类型、实际长度与 `plen` 不符、`plen` 超限、CRC 失败的报文直接丢弃并继续等待。
无载荷消息必须满足 `plen = 0`。`Frame` 内嵌缓冲上限为 96 字节，超出上限的帧会被拒绝。
接收路径先 `parsePacket()` 拉包再 `read()`（ESP32 上 `available()` 在解析前恒为 0）。
一次只解码一个数据报；所有帧均受同一个等待截止时间约束，坏包洪流不会延长超时。

| 消息 | 值 | 当前用途 |
| --- | --- | --- |
| `HELLO` | `0x01` | 广播节点存在，空载荷 |
| `HANDSHAKE` | `0x02` | 请求建立复制通道；已知邻居定向发送，无邻居时广播寻宿主 |
| `OFFER` | `0x03` | 携带完整基因组（65 字节） |
| `ACK` | `0x04` | 确认握手；接收方解析校验通过后也回 ACK 作为接收确认 |
| `NOTE` | `0x05` | 兼容保留：新固件不再发送（与 `OFFER` 载荷重复），接收方仍能处理 |
| `BYE` | `0x06` | 会话结束通知，空载荷 |

`OFFER` 载荷即完整基因组字节 `[genome:65]`（v1 的 `[solved:1][fitness:2]` 前缀与基因组内字段重复，已移除）。
当前没有分片；65 字节远小于 `MTU = 512`。

### 会话流程

```
发送方                                接收方
  | --- HANDSHAKE（定向或广播）---> |   收到即回 ACK
  | <----------- ACK ------------- |
  | --- OFFER [genome:65] -------> |   解析 + CRC/版本/字段/指纹校验
  | <----------- ACK ------------- |   校验通过才回（接收确认）
  | --- BYE ---------------------> |
```

- 发送方等待 ACK 期间：对他人的 `HANDSHAKE` 回 ACK，收到的有效 `OFFER`/`NOTE`
  暂存延迟队列，会话结束后以接收方身份处理。发送方只从 socket 等待新帧，避免取出缓存后重复入队。
  延迟队列最多 4 帧，满时丢弃最旧帧。
- 接收会话绑定首个有效握手/载荷的来源 IP 与 `src_sig`；其他来源的有效基因组留待后续会话处理，避免笔记与父本混用。
- `OFFER` 的 `src_sig` 必须与载荷中的 `self_sig` 一致，坏基因组不触发接收确认，也不会覆盖已有对象。
- 无 ACK 则如实失败，不再盲目发送 `OFFER`。
- 发送方须满足 `endPacket()` 成功且收到目标的 ACK 才返回成功；`BYE` 在确认等待结束后发送。
  ACK 的格式仍为空载荷，确认的限制见下文。

## 基因组（65 字节，version = 2）

| 偏移 | 字节数 | 字段 |
| --- | --- | --- |
| 0 | 1 | `version`，当前为 2（v1 旧布局会被拒绝） |
| 1 | 2 | `generation` |
| 3 | 2 | `fitness`，`pipelineRate × 10000`（0～10000） |
| 5 | 2 | `solved`，16 位位图，覆盖 `N_STEPS = 10` |
| 7 | 4 | `parent_sig` |
| 11 | 4 | `self_sig` |
| 15 | 40 | `int8` 权重，网络维度 8→4→2 |
| 55 | 8 | `int8` 笔记 |
| 63 | 2 | CRC16，覆盖前 63 字节 |

`self_sig` 使用 FNV-1a 计算：先把该字段清零，再对前 63 字节取指纹。
它是内容指纹；不同节点可以持有相同基因组，自接收按来源 IP 过滤。CRC 和指纹均不提供身份认证。

接收时同时检查版本、CRC、`solved` 的高 6 位为零、`fitness = computeFitness()` 和指纹一致性。
本地修改后调用 `Genome::refresh()` 更新适应度与指纹；CRC 在序列化时生成。

`fitness` 在进化和接收孵化后刷新，作为跨节点可比的模型适应度；
收养条件为「适应度不降且步数不减」。
`generation` 在 65535 饱和，不回绕到 0；本机统计跟随当前收养的基因组代次。

## 进化语义（当前实现）

- 权重变异为对称扰动 `-15..+15`（每基因位默认 5% 概率）。
- 接收方孵化时使用减半变异率 `2.5%`，避免系统性削弱强基因组。
- `PERM` 决策带 75% 探索地板：脑拒绝时仍以 75% 概率放行，维持感染压。
- 仅真实传输（成功或失败）触发遗忘/变异；主动跳过（SKIP）不奖不罚。
- 冷却自适应：成功 1500 ms、失败 5000 ms、跳过 1000 ms。
- TinyBrain 用 32 位累加器保存乘积之和，避免满幅 `int8` 输入/权重使 16 位累加器溢出。
- Wi-Fi 断开即视为网络未就绪，重连时重建 UDP socket 和邻居表；收包后仍检查心跳与主动传播时机。

## 已知实现限制

- **CRC 与指纹不提供身份认证。** 任何知道布局的节点都能伪造基因组。
- **无分片机制。** 载荷超过 `MTU` 的帧无法传输（当前基因组 65 字节，不受影响）。
- **v2 与 v1 固件不互通。** `deserialize` 严格校验 `version`，混网时旧固件帧被丢弃。
- **记忆经验（note）为 8 槽、步骤为 10 步。** 第 8、9 步与第 0、1 步共用槽位，
  标记中带步号（`0x40 + step`）避免误清，但同槽经验仍互相覆盖。
- **接收确认依赖 UDP。** 确认 ACK 丢失会使成功传输被判为失败（触发一次额外遗忘）。
- **ACK 没有会话号或阶段标记。** 握手 ACK 与接收 ACK 格式相同，延迟或重复的握手 ACK 可能被当作接收确认，不保证可靠交付或恰好一次处理。
- **同时发送仍可能超时。** 两端都处于发送等待时，对方的 `OFFER` 要等本次会话结束后处理，可能来不及确认；截止时间避免永久等待，但不能保证并发复制成功。
- **验证范围为本机回归与固件编译。** 回归测试使用 Arduino/Wi-Fi/UDP 桩执行实际 C++ 模块；多板通信、广播寻宿主、确认时序均需硬件实测。

Python 模拟器独立于 UDP 实现，使用四阶段概率模型；模拟概率不代表硬件传输成功率。
